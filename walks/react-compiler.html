Before: one TypeScript plugin behind Babel

Source is parsed by Babel. The TS compiler relies on Babel’s scope analysis, lowers to HIR, runs passes, and writes JavaScript back through Babel.

Component.jsx

Unchanged input. A React function component the compiler may memoize.

parser host Babel AST + scopes The only door. Parser and scope analysis live here.

The TypeScript compiler never owned parsing. It consumed Babel’s tree and Babel’s bindings, then emitted Babel nodes.

Why this became a bottleneck

Every integration had to speak Babel. Native parsers (OXC, SWC) could not call the compiler without a JS round-trip.

compiler TS compiler HIR, CFG, SSA, same pass list. Pointer-heavy.

This is the program being ported, not replaced. Pass order is the compatibility contract with 1,725 fixtures.

memoized JS

Output still looks like a Babel plugin result: hoisted constants, cache slots, skipped components.

03

After: one Rust core, three front doors

Integrations convert native ASTs into the Rust Babel-AST plus scope info, call the compiler, and convert back. Babel is a guest now, not the only host.

parser host Babel Still supported. No longer the only door.

The Babel plugin remains the compatibility path. It serializes the AST into Rust and back, which is why “3× as a plugin” is slower than the transform itself.

Serialization tax

The transform can be ~10×; the plugin is ~3× because the bridge copies the tree. Native OXC/SWC paths skip this once they are wired through.

parser host OXC Rust parser. Thin adapter crate in this repo.

OXC already speaks Rust. The adapter maps OXC nodes into the compiler’s Babel-shaped AST so the core never takes an OXC dependency.

Why a crate in the React repo

The integration layer can change without waiting on the OXC release train. Same idea for SWC.

parser host SWC Speedy compiler. Same adapter pattern as OXC.

Convert in, compile, convert out. End-to-end scripts already compare OXC and SWC examples against TypeScript output.

compiler Rust compiler react_compiler crate. Arenas, not pointers.

Hosts must still supply scope analysis. The crate does not re-derive bindings.

storage Arena + index Typed arenas replace the TS object graph.

Functions, instructions, and types are stored in arenas and addressed by index. That is the main Rust-shaped change; the pass list is not.

What an index buys

Copying an id is cheap, graphs are explicit, and the compiler can snapshot IR after each pass for the port tests.

same JS

Fixture output is compared against the TypeScript compiler, not rewritten to a new IR-on-the-page format.

04

Inside, the pipeline is the old one

AST lowers to a high-level IR with a control-flow graph and SSA. Passes run in the same order as TypeScript. Rust mainly changes how values are stored.

AST

Babel-shaped, regardless of which host produced it.

ir HIR · CFG · SSA The working representation. Passes mutate this.

High-level IR plus a control-flow graph in SSA form. This is what test-rust-port.sh dumps after every pass.

Pass order is the contract

If a pass moves, fixtures fail. The port’s job was to match TypeScript, not to invent a smarter pipeline.

HIR′

Same IR after inference, memoization, and the rest of the TS pass list.

AST

Back to Babel-AST so the host can print JavaScript.

storage TS: pointers Object graph. Cheap in a GC language.

The TypeScript compiler could point anywhere. Rust cannot do that without a lifetime puzzle, so the port did not try.

storage Rust: arena + index Ids instead of references.

This is the one structural change inside the pipeline. Reviewers looking for “a new compiler” will not find one here.

05

Correctness was checked at two depths

yarn snap --rust compares final JS and errors. A separate script diffs compiler state after every pass, which is how the port was kept honest.

test 1,725 snap fixtures Codegen and errors vs the TS plugin.

If printed JS or the diagnostic set diverges, the fixture fails. This is the user-visible contract.

test test-rust-port.sh IR after pass N, ids normalized.

Catches a pass that happens to emit the same JS for the wrong reason. The e2e script also runs the OXC and SWC examples against TS, comparing final code only.

Why normalize ids

Arena indices will not match TypeScript object identities. The dump strips those so the comparison is about shape, not allocator luck.

What to watch next

Scope analysis still comes from the host. Returning a whole program should become a list of patches. Native OXC/SWC paths should beat the Babel plugin once serialization is out of the way.

host contract Host scopes Still required. Not ported.

Each host already computed bindings. The crate consumes that map. A future pass could grow a native scope analyzer; this PR does not.

planned Full AST replace Today the host swaps the whole tree.

The intended shape is a list of patches so hosts that already own a tree do not rebuild it.

cost Babel serialize The remaining tax on the plugin path.

Do not read the 3× plugin number as the ceiling. The transform is already faster; the bridge is the drag.

native OXC / SWC Should be faster still, no JS round-trip.

Once serialization is out of the way, these are the paths that should show the 10×-class numbers in production builds.
