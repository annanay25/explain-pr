01

The page used to download every metadata file. Now it reads a catalog.

Opening one tenant’s blocks page listed every folder and fetched a file per block — often enough to time out. It now reads the catalog the compactor already writes, then lets you filter and page. A Scan bucket checkbox still does the old listing when you need brand-new blocks.

02

The handler no longer lists storage itself

A new chooser tries the catalog first. Filters and paging live on a small options struct. Extra columns download full metadata only for the page you can see, never more than 1000 files.

function BlocksHandler Entry point. Parses the form, then asks for a block list.

Used to call LoadMetaFilesAndMarkers itself. Now it calls loadBlocksPageData, then filter and page, then extra metadata only if needed.

function loadBlocksPageData Tries the catalog. Falls back to a full listing.

New. Calls loadBlocksFromBucketIndex, or scanBlocksFromBucket when the catalog is missing or broken.

function loadBlocksFromBucketIndex One catalog file. Short records.

New. Turns catalog rows into block records. Size, samples, and parent lists are missing until you ask for them.

function scanBlocksFromBucket The old listing, wrapped.

Still calls LoadMetaFilesAndMarkers. Scan bucket, JSON, and catalog fallback all land here.

function filterBlocks Keeps matching blocks. No storage reads.

Method on the options struct. Block ID (exact, case-insensitive), created time, sample time range, compaction level, deletion marks. All filters are AND.

function pageBlocks Takes one page of the matches.

Default page size 100 in a browser. Zero means all. A page past the end shows the last page.

function LoadMetaFilesForBlocks Full metadata for the rows you can see, not the whole tenant.

New helper in listblocks. Fetches known paths; it does not list folders. If you asked for all rows plus extra columns, page size is forced to 1000 so this cannot become a full listing again.

field metasAreComplete False after a catalog read. True after a full listing.

If this is false and you asked for extra columns, the handler downloads metadata only for the current page.

The admin HTML is the thing that changed. Object storage is read less by default, not written. Scripts that ask for JSON still get the old full listing. Hold the PR if a browser visit can become a full listing again.
