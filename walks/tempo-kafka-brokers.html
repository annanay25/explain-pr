01

Tempo used to start Kafka from one address. It can now try several.

Many Kafka setups give you several broker hostnames and no single failover name. You can pass all of them. After Tempo connects, Kafka still tells it the rest of the cluster.

process Tempo ingest Reads one address, then asks that broker for the rest of the cluster.

Before this PR, ingest Kafka started from a single host:port. If that host was down, Tempo never got cluster metadata.

setting ingest.kafka.address One host and port. A list was not allowed.

This is the shared Kafka setting for Tempo ingest. It used to be a plain string, default localhost:9092. Issue #7880 is that many Kafka clusters publish several broker addresses instead of one highly available hostname.

Kafka One broker If that one host is down at startup, Tempo cannot connect.

Kafka clients only need a starting address to learn the rest of the cluster from metadata. One host is enough when it is always reachable. It is not enough when operators hand you kafka-1, kafka-2, and kafka-3 with no load-balancer name.

process Tempo ingest Seeds every starting address, then learns the rest from Kafka.

After this PR, ingest Kafka can start from one host, a comma-separated string, or a YAML list. Any reachable seed is enough to get cluster metadata.

setting ingest.kafka.address One host, a comma-separated string, or a YAML list.

Existing address: kafka:9092 configs keep working. Flags take commas. YAML also accepts a list of hosts. Docs and the changelog say all three forms are valid. After connecting, Tempo still discovers remaining brokers from Kafka metadata.

Kafka Broker list Any one of these can get Tempo into the cluster.

These are bootstrap seeds, not the full membership list. The Kafka client tries them, then uses cluster metadata for the topic’s brokers. This matches how Grafana Mimir already documents comma-separated Kafka addresses.

02

One reachable starting broker is enough. Zero still means no startup.

Let’s take an example: User has three Kafka starting addresses. Assume broker A is down, broker B is reachable, and broker C is only a backup. Follow three startup cases to see exactly what the new list changes.

First User starts Tempo with A, B, and C. Before, the setting could hold only A and startup failed there; now the client receives all three seeds, B answers, and Tempo gets cluster metadata.
Next User keeps an old one-address config for B. The parser makes a one-item seed list, B returns metadata for the cluster, and startup works exactly as before.
Finally every configured seed is unavailable. Tempo tries the whole list but receives no metadata, so startup still fails. This change removes dependence on one chosen seed; it does not make Kafka outages survivable.
person User Tries a multi-address config, an old single address, and a full outage.

The hostnames are illustrative. The important cases are one reachable seed, one legacy seed, and no reachable seed.

process Tempo ingest Starts the Kafka client with every parsed seed.

Distributor, live store, and block builder all use the shared Kafka client options changed by this PR.

normalized setting Seed list Contains one or several starting addresses after parsing.

A plain string, comma-separated string, or YAML list becomes the same KafkaAddresses value. These are starting points, not a complete membership list.

downstream behavior Kafka cluster Any reachable seed can return metadata for the real cluster.

The unchanged Kafka client tries the supplied seeds. Once one answers, cluster metadata—not the configuration list—tells the client which brokers own the topic.

03

Two edits turn configuration into the seed list Kafka already understands.

The new address type normalizes every supported input. The shared client setup then passes the complete list to Kafka instead of one string.

First: one address, comma-separated addresses, and a YAML list all become the same seed list. A flag replaces the localhost default instead of appending to it.
normalized value KafkaAddresses Stores one or several bootstrap addresses in one form.

New in pkg/ingest/config.go. Set handles flags, UnmarshalYAML accepts a string or list, and both use the same comma-splitting and trimming helper.

existing setting KafkaConfig.Address Keeps its name but changes from one string to the normalized list.

Existing address: kafka:9092 configuration remains valid. Empty input is still rejected.

Address string `yaml:"address"` Address KafkaAddresses `yaml:"address"` type KafkaAddresses []string func (a *KafkaAddresses) Set(value string) error { *a = parseKafkaAddresses(value) return nil } // UnmarshalYAML accepts one string or a list.
Then: every normalized address becomes a Kafka bootstrap seed. The unchanged client can get cluster metadata from whichever seed answers.
client option Bootstrap seeds Receives the entire address list instead of one value.

commonKafkaClientOptions is shared by the ingest processes. Variadic expansion is the line that makes the extra addresses matter at runtime.

behavior checks Compatibility tests Cover single values, lists, replacement of the default, and two brokers.

The tests guard the three claims from the example: old configs parse, multiple seeds survive one unavailable broker, and empty input cannot start ingest.

04

Public APIs and stored traces stay unchanged. Kafka startup is the risk.

Trace queries and storage work as before. The affected path is how every ingest process reads addresses and connects to Kafka.

API Public API Trace queries and OTLP still take the same requests.

No new HTTP or gRPC shape. Pushing spans, searching traces, and the query-frontend are unchanged. This PR only changes how Tempo finds Kafka, not what callers send it.

storage Databases Blocks and object storage are not rewritten.

Nothing in this diff migrates tenant data or changes how traces are stored after Kafka. A bad parse fails at connect time; it does not corrupt blocks.

login Auth Login, encryption, the topic name, and consumer groups stay as they were.

Those fields are still on KafkaConfig. This PR only changes the type of Address.

setting Operator config Same setting name. It now accepts a list of hosts.

ingest.kafka.address is the contract operators already use. A single host still works. A YAML list or comma-separated string is new. Writing config back always saves commas, not a YAML list.

ingest Kafka at startup Distributor, live store, and block builder all connect from that list.

If the list is parsed wrong, those processes cannot reach Kafka and ingest stops. Tests cover YAML lists, replacement of the default, empty input, and a two-broker fake cluster.

merge gate Do not merge if… A list loses addresses, a flag keeps localhost, or one unavailable seed still blocks a reachable one.

Also stop if an empty list passes validation or an existing one-address YAML file no longer starts Tempo.
