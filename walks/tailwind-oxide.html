Bug 1: walking the tree twice

Calling scan() already walked the filesystem. Reading .files afterwards walked it again. Small projects hid this behind mtime checks. Thousands of files did not.

call scan() Walk #1. Already has the file list internally.

Extraction needs to visit every source. Throwing that visit list away and walking again was the bug.

bug .files Walk #2. Should have reused walk #1.

Even a walk that only checks mtimes is expensive once the tree is huge. The fix is “candidates = scan(); files = scanner.files”.

A parallel filesystem walk helps a large repo and costs 20–50ms of overhead. That overhead is loud on a small repo. Oxide cannot see the future size of your tree.

Thread pool startup dominates. A synchronous first walk is the right default when you do not yet know the size.
