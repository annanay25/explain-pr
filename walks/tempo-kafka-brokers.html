01

Kafka ingest used to take one starting address. It now takes a list.

Many Kafka setups give you several broker hostnames and no single failover name. You can pass all of them. After Tempo connects, Kafka still tells it the rest of the cluster.

setting ingest.kafka.address One host and port. A list was not allowed.

This is the shared Kafka setting for Tempo ingest. It used to be a plain string, default localhost:9092. Issue #7880 is that many Kafka clusters publish several broker addresses instead of one highly available hostname.

Kafka One broker If that one host is down at startup, Tempo cannot connect.

Kafka clients only need a starting address to learn the rest of the cluster from metadata. One host is enough when it is always reachable. It is not enough when operators hand you kafka-1, kafka-2, and kafka-3 with no load-balancer name.

setting ingest.kafka.address One host, a comma-separated string, or a YAML list.

Existing address: kafka:9092 configs keep working. Flags take commas. YAML also accepts a list of hosts. Docs and the changelog say all three forms are valid. After connecting, Tempo still discovers remaining brokers from Kafka metadata.

Kafka Broker list Any one of these can get Tempo into the cluster.

These are bootstrap seeds, not the full membership list. The Kafka client tries them, then uses cluster metadata for the topic’s brokers. This matches how Grafana Mimir already documents comma-separated Kafka addresses.

02

One new type accepts three ways of writing the same list.

A YAML string, a comma-separated string, or a YAML list all become the same list of hosts. Flags use commas and replace the default. The Kafka client then starts with every host in that list.

type KafkaAddresses A list of host:port pairs, not a single string.

New in pkg/ingest/config.go. It implements flag parsing and YAML so KafkaConfig.Address can stay one field. Docs still describe the flag as a string, on purpose, via FlagType.

function Set A flag value replaces the default. It does not append.

Needed because RegisterFlags first sets localhost:9092. If Set appended, passing -ingest.kafka.address=kafka-1:9092 would keep localhost in the list. Tests pin that a comma-separated flag becomes exactly those two hosts.

function UnmarshalYAML Tries a string first, then a list of strings.

A single string can still contain commas. A YAML list of hosts is also accepted. Writing YAML back always uses the comma-separated string form, not a list.

function parseKafkaAddresses Splits on commas, trims spaces, drops empty pieces.

Package helper in pkg/ingest/config.go, not a method on the type. Both Set and UnmarshalYAML call it. An empty list after this step fails validation with the same missing-address error as before.

type KafkaConfig Same Kafka settings as before. Address is now a list.

Used by the components that produce and consume ingest Kafka. Validate now checks that the list is not empty, instead of comparing the string to "".

field Address Typed as KafkaAddresses instead of string.

Tests across distributor, live store, block builder, and ingest helpers wrap a single host as KafkaAddresses{host}. The test Kafka helper now takes a slice of addresses too.

function commonKafkaClientOptions Passes every address into the Kafka client as a starting broker.

In pkg/ingest/writer_client.go. The call is now kgo.SeedBrokers(cfg.Address...). A test builds a two-broker fake cluster and checks a client can be created from that full address list.

Public APIs and databases are not in this change. Finding Kafka is.

Trace queries and storage stay as they were. The blast is the one address every ingest process uses at startup.

public API Not hit Trace queries and OTLP still take the same requests.

No new HTTP or gRPC shape. Pushing spans, searching traces, and the query-frontend are unchanged. This PR only changes how Tempo finds Kafka, not what callers send it.

databases Not hit Blocks and object storage are not rewritten.

Nothing in this diff migrates tenant data or changes how traces are stored after Kafka. A bad parse fails at connect time; it does not corrupt blocks.

auth Not hit Login, encryption, the topic name, and consumer groups stay as they were.

Those fields are still on KafkaConfig. This PR only changes the type of Address.

operator config Hit Same setting name. It now accepts a list of hosts.

ingest.kafka.address is the contract operators already use. A single host still works. A YAML list or comma-separated string is new. Writing config back always saves commas, not a YAML list.

Kafka at startup Hit Distributor, live store, and block builder all connect from that list.

If the list is parsed wrong, those processes cannot reach Kafka and ingest stops. Hold the PR if a YAML list keeps only the first host, a flag appends to localhost, or an empty list passes validation. Tests already pin those cases, plus a two-broker fake cluster.
